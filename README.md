# Hosts Monitor

Android-приложение + лёгкий агент для мониторинга небольшой фермы Linux-серверов
(2–5 машин: Matrix-сервер, VPN, relay и т.п.).

Приложение показывает:

- **Дашборд**: онлайн-статус, CPU/память/диски, uptime каждого сервера
- **Детали сервера**: спарклайны истории CPU/RAM/сети, load average, температура,
  swap, топ процессов, недавние failed SSH-логины, число соединений
- **Сервисы**: статус systemd-юнитов (nginx, matrix-synapse, wireguard, …)
- **Матрица связности**: кто кого видит — TCP-проверки с каждого сервера до пиров,
  с задержкой в мс
- **Алерты**: фоновый опрос (WorkManager) + уведомления, когда сервер/сервис
  падает или восстанавливается

Архитектура: на каждом сервере крутится однофайловый Python-агент (`agent/agent.py`,
только stdlib), отдающий JSON по HTTP. Приложение опрашивает агенты напрямую
(по белому IP или через VPN-приложение на телефоне). Токены хранятся в
EncryptedSharedPreferences.

## 1. Установка агента на сервер

```bash
# на сервере, из каталога agent/ репозитория:
sudo ./install.sh                 # ставит пример конфига + systemd-юнит
sudo nano /etc/servermon/config.json   # ОБЯЗАТЕЛЬНО: смените token!
```

Конфиг:

```json
{
  "listen_host": "0.0.0.0",
  "listen_port": 8443,
  "token": "длинная-случайная-строка",
  "mounts": ["/", "/var"],
  "services": ["nginx", "matrix-synapse", "wireguard"],
  "peers": [
    { "name": "matrix", "host": "10.0.0.10", "port": 8443 },
    { "name": "vpn",    "host": "10.0.0.20", "port": 443  },
    { "name": "relay",  "host": "10.0.0.30", "port": 22   }
  ]
}
```

- `services` — systemd-юниты, чей статус (`active/inactive/…`) виден в приложении
- `peers` — **именованные** проверки TCP-доступности с этого сервера. Имя пира
  должно совпадать с именем соответствующего сервера в приложении, тогда в
  «Матрице связности» строки и столбцы сойдутся. Порт должен быть TCP (для
  wireguard используйте порт TCP-сервиса, который живёт за ним, например relay)
- `mounts` — точки монтирования для контроля места

Проверка локально на сервере:

```bash
systemctl status servermon-agent
curl -s http://127.0.0.1:8443/health
curl -s -H "X-Auth-Token: ВАШ_ТОКЕН" http://127.0.0.1:8443/metrics.json
```

### Безопасность

- Агент — plain HTTP с токеном. **Рекомендуется** держать порт агента доступным
  только внутри VPN/локальной сети, либо закрыть его nginx с TLS:
  `location /metrics.json { proxy_pass http://127.0.0.1:8443; }` — тогда в
  приложении указывайте `https://сервер/` (или `https://сервер/agent`).
- Токен передаётся в заголовке `X-Auth-Token`.

## 2. Сборка APK

APK собирает GitHub Actions: сделайте push в репозиторий → вкладка **Actions** →
workflow **Build APK** → артефакт `hosts-monitor-debug-apk` → скачайте и
установите на телефон (разрешите установку из неизвестных источников).

Локально: `./gradlew :app:assembleDebug` (нужен JDK 17).

## 3. Настройка приложения

**Mesh-режим: один скрипт на все сервера**

1. Сначала добавьте **все** серверы в приложении (Настройки → «+»: имя, URL агента, будет общий токен)
2. **Настройки** → **Генератор агента** → **Сгенерировать скрипт (один на все сервера)**:
   внутрь зашиты общий токен и список всех узлов (каждый агент сам узнаёт себя и не проверяет сам себя)
3. **Поделиться** → Termius (сниппет) или **Сохранить файл** → SFTP; один и тот же файл — на каждый сервер: `sudo bash servermon-install.sh`
4. В приложении: **детали сервера → ⚙︎ Отслеживание** — агент отдаёт список сервисов и процессов,
   выбираете нужные галочками → «Сохранить» (выбор отправляется агенту и переживает перезапуск)
5. **Релей**: если сервер недоступен с телефона напрямую, но доступен с другого сервера —
   дашборд покажет его состояние с жёлтой точкой «через <сервер>» (uptime, CPU, RAM из отчёта соседа).
   Алерт «упал» приходит только если сервер не виден ни напрямую, ни через одного из соседей.

Классический путь (если удобнее руками):

1. Откройте приложение → **Настройки** → «+»
2. Введите имя (например `matrix`), URL агента (`http://10.0.0.10:8443`) и токен
3. Повторите для каждого сервера
4. Настройте интервал фонового опроса (мин. 15 мин) и пороги алертов

Важно: телефон должен иметь доступ к агентам — по белым IP или через VPN-приложение
на самом телефоне (тогда доступны и внутренние адреса 10.x.x.x).

## Структура репозитория

```
agent/                  # агент для серверов (Python 3, stdlib)
  agent.py              # однофайловый агент: /metrics.json + /health
  config.example.json
  install.sh            # systemd-юнит + установка
app/                    # Android (Kotlin, Jetpack Compose, Material 3)
.github/workflows/android.yml  # CI: selftest агента + сборка APK
```

## Траблшутинг

| Симптом | Причина |
|---|---|
| В приложении «неверный токен (HTTP 403)» | Токен в приложении ≠ токен в config.json |
| Сервис `unknown` | systemctl недоступен агенту; проверьте `journalctl -u servermon-agent` |
| Пир красный, но сервер доступен | Порт в `peers` не TCP или закрыт файрволом |
| Уведомления не приходят | Дайте приложению разрешение на уведомления и не выключайте оптимизацию батареи |
