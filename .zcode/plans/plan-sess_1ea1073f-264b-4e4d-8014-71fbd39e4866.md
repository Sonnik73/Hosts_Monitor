# ServerMon — Android-приложение для мониторинга серверов

## Context

У пользователя 2–5 Linux-серверов с разными ролями (Matrix-сервер, VPN, relay). Нужно Android-приложение для ежедневной диагностики: нагрузка, память, диски, статус сервисов, связность серверов друг с другом. Решение: **лёгкий агент на каждом сервере (Python, только stdlib)** + **нативное Kotlin-приложение (Jetpack Compose)**. APK собирается через GitHub Actions в пустой репозиторий «hosts-monitor».

Телефон достаёт агентов напрямую (по белому IP или через VPN-приложение на телефоне) — это покрывает сценарий relay→VPN.

## Состав проекта

```
hosts-monitor/

├── app/                      # Android-проект (Gradle, Kotlin, Compose)
├── .github/workflows/android.yml
└── README.md                 # установка агента, настройка приложения, сборка
```

## 1. Агент (`agent/agent.py`)

Однофайловый Python-скрипт (работает на любом Linux с python3), HTTP-сервер на stdlib (`http.server`), отдаёт `/metrics.json` (защита — токен в заголовке `X-Auth-Token`, настраивается в конфиге):

- **Система**: uptime, hostname, load average (1/5/15), кол-во ядер
- **CPU%**: расчёт по `/proc/stat` между запросами
- **Память**: из `/proc/meminfo` (used/total, swap)
- **Диски**: занятость по `os.statvfs` для точек монтирования из конфига
- **Сеть**: RX/TX счётчики интерфейсов (`/proc/net/dev`), скорость за интервал
- **Сервисы**: `systemctl is-active <unit>` для списка из конфига (matrix-synapse, wireguard, nginx и т.п.)
- **Матрица связности**: TCP-connect/ping до пиров из конфига (host:port) + latency — замеряется **с самого сервера**, что и нужно
- **Диагностика**: top-5 процессов по CPU/RAM, недавние failed SSH-логины (`journalctl`), кол-во установленных соединений, температура CPU (если есть)

Конфиг — `/etc/servermon/config.json`: токен, порт, список сервисов, точки монтирования, пиры (`name, host, port`). `install.sh` ставит systemd-юнит с автозапуском.

## 2. Android-приложение (`app/`)

Kotlin + Jetpack Compose + Material 3, minSdk 26, targetSdk 34. Ключевые библиотеки: OkHttp, kotlinx-serialization, WorkManager, DataStore.

**Экраны:**
- **Дашборд** — карточки серверов: онлайн/оффлайн, CPU%, RAM, диск, uptime, цветовая индикация порогов (warn/crit настраиваются)
- **Детали сервера** — графики-спарклайны (CPU/RAM/сеть, Canvas без тяжёлых зависимостей), статус сервисов с возможностью перезапроса, топ-процессы, failed SSH-логины, диски
- **Матрица связности** — таблица N×N «кто кого видит»: зелёный/красный + latency; видна агрегированно со всех агентов
- **Настройки** — добавление серверов (имя, URL агента, токен), интервал опроса, пороги алертов, тёмная/светлая тема

**Фон и уведомления:** WorkManager периодически (мин. 15 мин, настраиваемо) опрашивает агенты; при переходе сервера/сервиса в offline или превышении порога — push-уведомление. История метрик хранится локально (in-memory ring buffer + DataStore для последнего состояния — Room не нужен для 2–5 серверов).

**Безопасность:** токен в зашифрованном хранилище (EncryptedSharedPreferences), поддержка http (внутри VPN) и https.

## 3. GitHub Actions (`.github/workflows/android.yml`)

Пуш в репозиторий → сборка `assembleDebug` (и релизной подписи debug-ключом) → APK как артефакт для скачивания. Плюс быстрый smoke-тест агента (`python3 agent.py --selftest`).

## 4. README

Установка агента (scp + install.sh), примеры конфигов для трёх ролей (matrix/vpn/relay), как добавить серверы в приложение, как скачать APK из Actions.

## Порядок реализации

1. Скелет репозитория: Gradle-проект, workflow, README
2. Агент: agent.py + конфиг + install.sh
3. Android: данные/сеть → дашборд → детали сервера → матрица связности → настройки → WorkManager/уведомления
4. Проверка

## Верификация

- Агент: запустить локально с тестовым конфигом, проверить curl'ом `/metrics.json` (токен, корректность JSON всех метрик, selftest-режим без systemd — на Windows-хосте части метрик будут 0, это ожидаемо)
- Приложение: `gradlew assembleDebug` в CI зелёный; для проверки UI локально — скриншоты эмулятора недоступны, поэтому компиляция + unit-тест парсинга JSON агента (тест-фикстура с реальным выводом агента)
- Финальная проверка на реальных серверах — за пользователем: установить agent.py, добавить серверы в приложение, скачать APK из Actions
